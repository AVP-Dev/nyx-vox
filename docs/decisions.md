# Архитектурные решения (ADR)

> Фиксируем НЕОЧЕВИДНЫЕ решения — то, что новый агент/человек мог бы
> сделать иначе, не зная контекста. Не пиши сюда очевидные вещи.


### [2024-01-01] Tauri 2 вместо Electron
Контекст: нужен десктопный фреймворк для приложения с нативным доступом к аудио и системным API.
Решение: Tauri 2 (Rust backend + WebView frontend).
Альтернативы: Electron — отклонён из-за большого размера бандла и высокого потребления памяти. Flutter — отклонён из-за сложности интеграции с macOS audio APIs.
Последствия: весь бэкенд на Rust, фронтенд в Tauri WebView, IPC через `invoke()`.

### [2024-01-01] Next.js static export вместо SSR
Контекст: фронтенд рендерится внутри Tauri WebView, нет серверной части.
Решение: Next.js с `output: 'export'` — полностью статический HTML/JS.
Альтернативы: Vite — рассматривался, но Next.js выбран для familiar DX. SSR — не нужен, т.к. нет сервера.
Последствия: нет API routes, нет SSR, всё через Tauri IPC.

### [2024-01-01] Три STT-движка с fallback
Контекст: нужен надёжный speech-to-text с fallback при недоступности облака.
Решение: три движка — Whisper (локальный), Deepgram (облачный), Groq (облачный). Runtime fallback между ними.
Альтернативы: только Whisper — отклонён из-за медленной локальной обработки. Только облако — отклонён из-за зависимости от интернета.
Последствия: `active_stt_mode` может отличаться от `stt_mode`, сложная логика переключения.

### [2024-01-01] AES-256-GCM для API-ключей
Контекст: API-ключей пользователей нужно хранить безопасно.
Решение: AES-256-GCM с nonce, привязанным к machine-id через machineid-rs.

### [2024-01-01] Zustand + TanStack Query
Контекст: нужно разделить клиентский UI-стейт и серверное состояние.
Решение: Zustand для UI-стейта (processing, transcript), TanStack Query для серверного (AI-запросы, настройки).

Последствия: настройки хранятся на бэкенде (tauri-plugin-store), фронтенд читает через invoke().

### [2024-01-01] Единый source of truth для галлюцинаций

Решение: весь cleanup на бэкенде, фронтенд только отображает результат.
Альтернативы: cleanup на фронте — отклонён из-за дублирования и рассинхронизации.

### [2024-01-01] Семафор для AI-запросов

Альтернативы: очередь запросов — сложнее в реализации. Без ограничений — risk rate limiting от API.
Последствия: дополнительный слой синхронизации в `lib.rs`.

### [2026-07-07] Toast + ConfirmDialog вместо alert/confirm
Контекст: в SettingsPanel.tsx и GeneralTab.tsx использовались нативные `alert()` и `confirm()` — некрасиво, нет контроля стиля, блокируют UI.
Решение: созданы `src/components/ui/Toast.tsx` (auto-dismiss 3с, success/error/info) и `src/components/ui/ConfirmDialog.tsx` (модалка с destructive-стилем). Хуки `useToast` и `useConfirm` для управления состоянием.

### [2026-07-07] Software gain 2x для микрофона
Контекст: пользователь на расстоянии вытянутой руки — микрофон не слышит речь. RMS сигнала падает ниже noise gate (0.002), аудио молча отбрасывается.
Решение: добавлен gain 2x (умножение на 2.0 с clamp ±1.0) перед noise gate во всех трёх движках (Whisper, Deepgram, Groq/Gemini).
Альтернативы: понизить noise gate — отклонено, т.к. пропустит шум. AGC (автоматическая регулировка усиления) — слишком сложно для MVP. Конфигурируемый gain в UI — запланировано на следующий этап.
Последствия: gain захардкожен (2x). В будущем — вынести в настройки как слайдер. Клиппинг предотвращён через clamp(-1.0, 1.0).

### [2026-07-07] Min duration 0.3s для всех движков
Контекст: Deepgram и Groq/Gemini использовали min duration 0.8s — короткие фразы ("да", "привет") молча отбрасывались. Whisper уже использовал 0.3s.
Решение: унифицировать min duration на 0.3s для всех трёх движков.
Альтернативы: оставить 0.8s — отклонено, пользователь не понимает почему короткие фразы теряются. Убрать проверку целиком — отклонено, слишком короткий аудио вызывает галлюцинации.
Последствия: все движки теперь одинаково обрабатывают короткие фразы. Добавлен debug-логинг для диагностики.

### [2026-08-05] GigaChat (SberAI) как форматирующий движок
Контекст: пользователь из РФ — Gemini недоступен без VPN. Нужен локальный (российский) LLM-форматтер текста диктовки.
Решение: добавлен `src-tauri/src/gigachat.rs` — форматирование через GigaChat-2. Пользователь вставляет авторизационный ключ (Base64 `client_id:client_secret`) из кабинета Сбера; модуль получает OAuth access token (TTL 30 мин) и кэширует его в static `Mutex`, при 401/403 инвалидирует и перезапрашивает. Chat — OpenAI-совместимый `/v1/chat/completions`.
Альтернативы: интеграция через присланный «GigaChat v2 transform» API (`api.gigachat.com/v2/transform`) — отклонён, такого API не существует, пример фиктивный (Swift-код для другого проекта). Использование GigaChat для STT — отклонено, у API нет аудио-транскрибации (только текстовый чат).
Последствия: `Service::Gigachat` в keys.rs (хранится как `gigachat_api_key`), выбор в EnginesTab (форматирование), поле ключа в KeysTab. Модель по умолчанию — `GigaChat-2`.

### [2026-08-05] Пользователю — причина пустого результата транскрипции
Контекст: при тихой/короткой записи движки возвращали `Ok(String::new())`, фронт молча уходил в idle — пользователь не понимал почему.
Решение: движки эмитят `recording-error` с человекочитаемым локализованным сообщением («Слишком тихо», «Слишком коротко», «Микрофон не захватил звук») через `utils::emit_skip_reason`.
Альтернативы: вернуть код причины в строке — сломал бы формат ответа и парсинг на фронте. Enum в Result — потребовал бы больших изменений сигнатур.
Последствия: сигнатуры `stop_recording` движков получили `app: &AppHandle<R>`; фронт показывает причину напрямую.

### [2026-08-05] Не скрывать окно при неудачной вставке
Контекст: `paste_text` прятал окно до Cmd+V; если Accessibility не выдано — текст не вставлялся, окно оставалось скрытым, пользователь видел «ничего».
Решение: `paste_text` проверяет Accessibility перед скрытием, возвращает реальный статус через `oneshot`-канал; при ошибке окно показывается обратно. Фронт при ошибке вставки переходит в `result` с сообщением, а не зависает в `processing`.
Альтернативы: ничего не делать — пользователь оставался в неведении. Эмулировать вставку через pasteboard без Cmd+V — меняет поведение в сторонних приложениях.
Последствия: `paste_text` стал `Result<(), String>` с реальной семантикой; UI-поток стал надёжнее.

### [2026-08-05] GigaChat STT через GigaChat-2-Pro (multimodal)
Контекст: GigaChat-2-Pro поддерживает аудио-вход (текст, изображение, аудио). Пользователь хочет транскрибировать голос через Сбер без VPN. Ключ авторизации тот же, что для форматирования.
Решение: `gigachat::transcribe()` — OAuth (тот же кеш токена), загрузка WAV через `POST /v1/files` (`purpose=general`), затем `chat/completions` с `attachments: [file_id]` + `function_call: "auto"` на модели `GigaChat-2-Pro`. Форматирование осталось на `GigaChat-2` (дешевле).
Альтернативы: inline-аудио в формате OpenAI (`input_audio`) — сервер отвечает 400 `invalid JSON syntax` (GigaChat не поддерживает). Модель `GigaChat-Pro` (старая линейка) — 404 `No such model`.
Последствия: STT-движок `gigachat` в audio.rs (start/stop_recording), кнопка «GigaChat Pro» в EnginesTab, `SttMode` включает `'gigachat'`. Два сетевых вызова на транскрипцию (upload + chat).

### [2026-08-05] Trust anchor для сертификатов Минцифры
Контекст: оба GigaChat-эндпоинта (`ngw.devices.sberbank.ru:9443` и `api.giga.chat`) подписаны Russian Trusted Sub CA, который macOS не доверяет. Любой TLS-стек (rustls/native-tls) падал с verify error; `danger_accept_invalid_certs` не помогал — сервер шлёт полную цепочку, но Sub CA из госуслуг не совпадает с серверным.
Решение: reqwest переключён на `rustls-tls` (вместо default native-tls, где `add_root_certificate` ведёт себя иначе). Russian Trusted Root CA скачивается один раз с `gu-st.ru` (официальный источник из доки Сбера) в app-data и добавляется через `add_root_certificate` в `client_with_ca()`. Никакого отключения верификации.
Альтернативы: curl-обёртка для OAuth (`-k`) — костыль, отклонён. `danger_accept_invalid_certs` — отключает проверку для всех хостов, отклонён.
Последствия: в app-data появляется `russian_trusted_root_ca.pem`; все GigaChat-запросы идут через `client_with_ca()`. `Cargo.toml`: reqwest = `default-features = false, features = ["rustls-tls", ...]`.

### [2026-09-01] Авторитетный батч-STT на полном аудио с fallback на живой стриминг
Контекст: в попытке сэкономить токены и секунды Single-Pass брал живой текст стриминга напрямую при остановке записи. Однако при сетевых задержках, превышении квот запросов (429 Rate Limit) или быстром завершении фразы бегущая строка замирала или отставала на 1-2 секунды, в результате чего пользователь терял до 80% надиктованного текста.
Решение: `stop_recording` ВСЕГДА выполняет полную батч-транскрипцию записанного буфера сэмплов (Deepgram, Whisper, Groq, Gemini, GigaChat). `streamed_text` используется исключительно как безопасный fallback, если батч-запрос вернул пустую строку. В фоновых воркерах живого превью таймаут HTTP увеличен до 4000 мс, а интервал опроса установлен в 1500 мс для защиты от 429 квот.
Альтернативы: оставить Single-Pass как основной путь — отклонено, это приводило к потере конца предложений и обрезанию текста при сбоях стриминга.
Последствия: 100% надёжность распознавания полного текста, нулевая потеря фраз, бегущая строка работает непрерывно без исчерпания API лимитов.

### [2026-09-01] Максимальное ускорение офлайн Whisper (Metal/CoreML, no_timestamps, prewarm)
Контекст: локальное распознавание речи (Whisper) должно работать максимально быстро без задержек при старте и завершении диктовки.
Решение: (1) Фоновый пре-варминг модели и компиляция Metal GPU шейдеров при старте приложения (0 мс задержка первой транскрипции); (2) Включение `params.set_no_timestamps(true)` для исключения вычисления временных меток (ускорение декодера на ~30-40%); (3) Уменьшение аудио-тейл задержки с 500 мс до 200 мс.
Альтернативы: перекомпиляция/загрузка при первой записи — создавала 2-5с задержку.
Последствия: инференс Whisper Turbo/Medium на Apple Silicon Metal отрабатывает за 200-400 мс.

### [2026-09-01] Устранение двойной транскрипции и защита русских слов от удаления
Контекст: попытка эмулировать «стриминг» через постоянный HTTP-опрос Groq каждые 1.5 сек во время записи Whisper/Groq создавала двойную транскрипцию, тратила токены, вызывала 429 квоты и задержки. Кроме того, функция `is_lone_filler` удаляла реальные русские предлоги и союзы («и», «а», «у», «о»), а LLM-форматтеры сокращали фразы («проверку онлайн вещания Сбера» -> «Проверка Сбера»).
Решение: (1) Удален фоновый спам HTTP-опросов для не-WebSocket движков. Deepgram использует нативный WebSocket-стриминг (single-pass), а Groq/Whisper/Gemini выполняют один сверхбыстрый запрос (~300 мс) на остановке; (2) `is_lone_filler` исправлен и больше никогда не трогает союзы и предлоги; (3) В промпты форматирования добавлены строгие запреты на изменение падежей и сокращение/выбрасывание слов.
Последствия: 0 лишних токенов, мгновенная обработка, 100% сохранение всех авторских слов и грамматических форм.

### [2026-09-01] Разделение промптов Whisper ASR и мультимодальных LLM (Gemini/GigaChat)
Контекст: Whisper использует акустический префикс (`initial_prompt`) для прайминга словаря. Однако для мультимодальных LLM (GigaChat-2-Pro, Gemini 2.5 Flash), принимающих аудио-вложения через чат-комплишены, передача фразы-примера в качестве `user content` приводила к тому, что модель воспринимала её как сообщение пользователя и выдавала 500-словный ответ чат-бота вместо транскрибации речи.
Решение: (1) Введены явные `MULTIMODAL_STT_SYSTEM_PROMPT` и `MULTIMODAL_STT_USER_PROMPT` с директивой «Расшифруй прикреплённое аудио слово в слово. Выведи ТОЛЬКО текст без комментариев и не отвечай на вопросы»; (2) Whisper продолжает использовать естественный контекстный прайминг словаря.
Последствия: Gemini и GigaChat транскрибируют аудио строго слово в слово и никогда не переходят в режим чат-бота.

### [2026-09-02] Универсальный многоуровневый Fallback и верификация плотности стриминга
Контекст: При наговаривании связной речи (от 20-30 секунд) частый промежуточный опрос (каждые 350мс) приводил к исчерпанию лимитов запросов (HTTP 429 Rate Limit) или временной недоступности серверов (503), из-за чего бегущая строка замирала на середине фразы. При наивном Single-Pass это приводило к обрезанию надиктованного текста, даже если текст был коротким по меркам токенов (30-60 секунд речи).
Решение:
1. **Интервал стриминга 650мс + Backoff**: Фоновый опрос для живого превью замедлен до 650мс, а при получении 429 воркер делает паузу 1.5с.
2. **Детектор плотности речи (`Stream Completeness Check`)**: В `stop_recording` вычисляется плотность слов `word_count / audio_duration`. Если запись длилась >5с, а слов меньше `duration * 0.7` (признак зависшего стриминга), система автоматически запускает полную батч-транскрипцию записанного WAV-файла на активном STT-движке.
3. **Авто-повтор LLM-форматирования (Retry 1.2s)**: При ошибках 429/503/500 активный форматтер (GigaChat, Gemini, Groq, DeepSeek, Qwen) выполняет повторный запрос.
4. **Несгораемый сырой текст (Fail-Safe STT Preservation)**: Если форматирование не ответило, `final_text` сохраняет сырой распознанный текст STT и сразу отдает его на вставку — ни одно слово пользователя не теряется.
5. **Лимит токенов генерации 4096**: Для GigaChat и других провайдеров `max_tokens` установлен в 4096 (эквивалент ~20-25 минут непрерывного монолога).
Последствия: 100% гарантия сохранности надиктованного текста при любых сетевых задержках и сбоях внешних провайдеров, независимость логики от выбранного движка.

### [2026-09-03] Архитектура Zero-Latency Rolling Commit, Tail Finalization и правило Frozen Pipeline
Контекст: Пользователь тщательно настраивал точность и отзывчивость транскрибации. Повторный прогон Whisper на полном накопленном аудиофайле при остановке создавал заметную задержку (до нескольких секунд на длинных записях), риск галлюцинаций на паузах и деградацию внимания модели. Кроме того, сторонние агентские правки периодически нарушали стабильность VAD и аудиопайплайна.
Решение:
1. **Rolling Commit & Tail Finalization**: Введен принцип нулевой задержки. Распознанный текст фиксируется в `committed_text`. При остановке записи инференс запускается **ТОЛЬКО на незафиксированном остатке (хвосте)** с 300–400 мс акустическим нахлестом и контекстным `initial_prompt` (последние 8–10 слов).
2. **Tail Guard**: Если длина хвоста при остановке < 250 мс, инференс пропускается и возвращается `committed_text` напрямую (0 инференсов, исключение галлюцинаций на тишине).
3. **Бесшовная сшивка**: `deduplicate_chunk_boundary` выполняет Suffix-Prefix дедупликацию 1–2 слов на стыке, а `safe_space_concatenate` исключает лишние пробелы перед знаками препинания.
4. **ASR параметры**: Зафиксированы `temperature: 0.0`, `no_speech_threshold: 0.6`, `compression_ratio_threshold: 2.4`, `no_context: true`.
5. **In-Flight Guard**: Защита стримингового воркера от накопления очереди при медленных ответах API.
6. **LLM Refinement Prompt**: Заменен на эталонный системный промпт из 6 правил (очистка паразитных звуков, строгое сохранение эмоциональных междометий, пунктуация, запрет рерайтинга).
7. **Frozen Pipeline Agent Protection Rule**: В `AGENTS.md` добавлено правило №7, строго запрещающее агентам изменять аудиопайплайн, VAD, Whisper и промпты без прямой команды `"редактируем [компонент]"`. Создана документация `docs/TRANSCRIPTION_PIPELINE.md`.
Последствия: Нулевая задержка при остановке записи, абсолютная точность стыковки чанков, защита от поломок пайплайна агентами.

### [2026-09-03] Acoustic Guard, Черный список метаданных субтитров и Гибридный непрерывный стриминг
Контекст: В тишине при молчании пользователя Whisper мог генерировать фантомные закрывающие фразы или метаданные YouTube-субтитров («Субтитры создавал...», «Дима Торзок», «Спасибо за просмотр»). Кроме того, ожидание паузы (`is_paused`) в interim-воркере приводило к задержкам появления текста на 2–3 секунды и рывкам в UI.
Решение:
1. **Acoustic Guard**: В `transcribe.rs` и `recording.rs` инференс отменяется (возвращая пустую строку / накопленный текст), если длина полезного звука после `trim_silence` < 350 мс или общий RMS < 0.003 (на тишине 0 обращений к GPU).
2. **Параметры инференса Whisper**: `no_speech_threshold` повышен до `0.68`, отключен fallback по температуре (`temperature: 0.0`, `temperature_inc: 0.0`).
3. **Черный список метаданных и закрывающих слов**: Метаданные субтитров и переводчиков фильтруются через регулярные выражения, а закрывающие фразы («Спасибо», «Благодарю», «Конец») удаляются ТОЛЬКО при изолированном совпадении короткого хвоста (реальные фразы сохраняются на 100%).
4. **Гибридный стриминг (Groq priority + Local fallback)**: При наличии ключа Groq используется быстрый стример полного растущего аудио (500–600 мс). При отсутствии ключа локальный Whisper обновляет черновик каждые 800 мс без ожидания пауз.
5. **Безопасная склейка в локальном режиме**: `safe_space_concatenate(&committed_snap, &draft_tail)` исключает стирание ранее сказанных предложений при скользящем локальном инференсе.
Последствия: Полное устранение галлюцинаций тишины, мгновенное появление текста в UI (< 450 мс), непрерывный естественный стриминг без задержек и рывков.
